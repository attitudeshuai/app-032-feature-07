# 花灯骨架放样与蒙面裁片 · Lantern Frame Lofting

纯前端工具：选灯型 → 填直径/高度/收口 → 出「每根竹篾截多长、弯什么角度」的骨架件表、带缝份的蒙面裁片、以及可 100% 打印的 1:1 放样图与备料单。无后端、无网络请求，断网可用。

## 技术栈

- Vue 3（`<script setup>` 单文件组件）+ TypeScript + Vite 6
- 状态：Vue 自带 `ref / reactive / computed / watch`（无 Pinia / Vuex）
- 额外依赖仅 `vue-router` 4（规格书要求的 6 个路由）
- 手写 CSS；无 UI 组件库、无图表库、无游戏引擎/物理库
- 字体、灯型数据包（`src/data/lantern-types.json`）全部本地打包，无外网 CDN

## 打印比例校验（1:1 闭环）

1. 按 100% 打印（关闭「适应页面」）→ 用钢尺量第 1 页校验尺 → 把实测长度填回 `/print/:id` 的「打印比例校验」卡片；
2. 页面按标称 100.0mm 算出**实测比例**（百分数 2 位小数）与偏差（mm 1 位小数，另给 cm 1 位小数）；
3. 偏差 ≤ 1.0mm 才把这次比例记到灯样上（`lantern.calibration`，本机存档）；超差则本套图纸判不可用，并给出改法：关闭「适应页面」重打 / 换更大幅面的纸 / 分幅打印；
4. 这一份比例是**唯一来源**：1:1 放样图每页角注、三份导出单子（构件清单 / 裁片清单 / 备料单 CSV）角注、骨架构件表与蒙面裁片页的「纸上读数」换算列、本机存档，全部由它算出（CHK-09 断言同源）；改纸张或搭接量后各出口一起刷新，仍按老环境显示的那一处会被点名；
5. 实测比例 ≠ 100% 时二选一（认下代价）：**按实测比例换算下料**（图纸照旧能用，实际下料 = 纸上读数 ÷ 比例，代价是每刀都要重新读数）或**重打到原大才放行**（纸上量多少是多少，代价是图纸与单子重出、已发的作废）；
6. 旧灯样没有校验记录时一律按「未测量」处理，不当成原大。

## 启动

```bash
npm install
npm run dev        # http://127.0.0.1:5173
npm run build      # vue-tsc --noEmit && vite build
npm run preview
```

## Docker 构建

```bash
docker compose build
docker compose up -d            # http://localhost:8112
curl http://localhost:8112/healthz
docker compose down
```

多阶段：`node:20-alpine` 构建 → `nginx:1.27-alpine` 只托管 `dist/` 与 `nginx.conf`（SPA 回退、哈希资源 immutable、index.html no-cache、gzip、SVG MIME、`/healthz` 健康检查）。
